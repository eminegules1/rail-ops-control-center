# Feature: End-to-end test coverage

**From build-plan:** feature 16
**Build attempt:** 1
**Status:** verified
**Branch:** feature/end-to-end-test-coverage

## Goal

Prove the whole pipeline works through its real entry points (Kafka in, HTTP and metrics out) with Testcontainers,
for the three flows the plan names: happy path, dead-letter path and Redis-down fallback. Add a JaCoCo coverage
report so the assignment rubric can see what the tests exercise.

Today's backend integration tests each cover one component (ingestion, retry, live state, reconciler, WebSocket,
dashboard service) and call services or repositories directly. None starts from a Kafka record and asserts what an
operator's client sees over HTTP, and there is no coverage report.

## In scope

- One new backend Spring Boot integration test class, `EndToEndIntegrationTest`, running the real application on a
  random port against Kafka, PostgreSQL and Redis containers, driving input only through Kafka
  (`KafkaTemplate`) and the HTTP API (`TestRestTemplate`), and asserting only through HTTP responses, the
  `/actuator/prometheus` output and the dead-letter topic.
- Flow 1, happy path: valid events published to `incident-events` appear through `GET /api/events`,
  `GET /api/events/{eventId}`, `GET /api/dashboard/summary`, `GET /api/services` and
  `GET /api/dashboard/recent-events`; a `PUT /api/events/{eventId}/status` is reflected by the same reads; the
  `ingestion.events{outcome=processed}` counter (Prometheus `ingestion_events_total`) rises by the number of
  distinct valid events. A redelivered duplicate `eventId` leaves the event count unchanged.
- Flow 2, dead letter: an unparseable payload and a schema-invalid payload published between valid events land on
  `incident-events.DLT`, never appear in `GET /api/events`, raise the `invalid` and `dlt` outcomes, and do not block
  the valid events around them.
- Flow 3, Redis down: with the Redis container paused (the `docker.pauseContainerCmd` pattern already used in
  `LiveStateReconcilerIntegrationTest`), `GET /api/dashboard/summary` and `GET /api/services` still answer 200 with
  values derived from Postgres, and a `PUT .../status` still answers 200; after Redis is unpaused, the same HTTP
  reads converge on the Postgres truth including that status change.
- JaCoCo coverage report for the `producer` and `backend` modules, generated by the existing `verify` commands.
- README: how to run the end-to-end test and where to open the coverage report.

## Out of scope

- Frontend coverage and browser or Playwright tests (no `Browser tests` command exists; frontend coverage needs a new
  dependency).
- Coverage thresholds or failing the build on low coverage.
- Ingestion while Redis is down as an end-to-end flow (component behavior is covered by the existing reconciler and
  updater tests).
- WebSocket assertions (already covered by `LiveUpdatesIntegrationTest`).
- CI wiring and Verify command (feature 18), compose startup hardening (feature 17), architecture and delivery docs
  (feature 19).
- Changes to production code. If a flow cannot be asserted without one, stop and raise it as a `/fix`.

  `backend/src/test/java/com/railops/backend/` with `@SpringBootTest(webEnvironment = RANDOM_PORT)`,
  `@Testcontainers`, and the same three `@ServiceConnection` containers and image tags as the other integration
  tests. Implement flow 1. Use a distinct service name and `eventId` prefix per test and read metrics as

  Done when: `mvn -B -pl backend -am -Dtest=EndToEndIntegrationTest -Dsurefire.failIfNoSpecifiedTests=false verify`

  duplicate handling and the processed counter delta.
- [x] 3. **Dead-letter flow.** Add flow 2, reading the DLT with the existing `DeadLetters.read` helper and

  Done when: the same command passes with the DLT test proving the invalid records reach the DLT, are absent from the
  events API, raise the `invalid` and `dlt` counters, and valid events published before and after them are served by

  `LiveStateReconcilerIntegrationTest` does (small window and short open-state wait) so the breaker trips and

  traffic through the API until the breaker closes, as the reconciler test does, then assert convergence.
  Done when: the same command passes with the test proving 200 responses and Postgres-derived summary and services
  during the outage, a 200 status change during the outage, and matching HTTP reads after recovery.
- [x] 5. **Full run, report and README.** Add a short README section (in the backend area near the existing

  Done when: `mvn -B -pl producer -am verify` and `mvn -B -pl backend -am verify` (Docker Desktop running) both pass,

## Data / contracts

- Endpoints under test, unchanged: `GET /api/events` (with `service` filter and pagination), `GET /api/events/{eventId}`,
  `PUT /api/events/{eventId}/status` with `{"status": "..."}`, `GET /api/dashboard/summary`, `GET /api/services`,
  `GET /api/dashboard/recent-events`, `GET /actuator/prometheus`.
- Topics: `incident-events` (key: service name) and `incident-events.DLT`.
- Metric: `ingestion.events` tagged `outcome` = `processed`, `invalid` or `dlt`. Counters live in a registry shared by
  every test in the class, so assert deltas.
- Event payload shape follows the JSON already used by the existing integration tests
  (`eventId`, `source`, `service`, `severity`, `message`, `status`, `timestamp`).
- JaCoCo output: `<module>/target/jacoco.exec` and `<module>/target/site/jacoco/` (HTML and XML). Generated files
  stay untracked; confirm `target/` is ignored by Git before finishing.

## Testing

- The end-to-end class is the deliverable; it runs under the existing Surefire `verify` command
  (`mvn -B -pl backend -am verify`) with Docker Desktop running. It cannot run in the dockerized-Maven fallback.
- Producer coverage verifies with `mvn -B -pl producer -am verify` (no Docker needed).
- No frontend commands are affected. No `Verify` command exists yet; none is run or claimed.
- Each flow test must fail if its behavior breaks: assert specific values (counts, statuses, service health), not
  only status codes.

## Notes for the AI

- Keep production code untouched; this feature adds tests and build configuration only.
- Reuse the container declarations, image tags, `DeadLetters` helper and pause/unpause pattern from the existing
  tests. Do not add a new test dependency; Awaitility, Testcontainers and `TestRestTemplate` are already available.
- Do not add thresholds, `check` goals, or other JaCoCo configuration beyond agent and report.
- Order independence matters: JUnit method order is not guaranteed, and the metric registry, Postgres and topics are
  shared inside the class.
- If the Redis-down flow proves flaky because of circuit-breaker timing, fix the test's waiting strategy; do not
  weaken assertions or change production timeouts.
- Do not record coverage percentages in the README; only the report location.
